feat: FAQ를 리뷰·상품정보에서 도출한 CEP로 구성하고, 근거가 있는데 탈락하던 게이트 결함 수정

**FAQ CEP 파이프라인 (5단계)**

- 추출 → 상황 분석 → CEP 도출 → 추천 질의 역설계 → 근거 기반 실현. 1~2단계는 신규 `review-cep` 모듈이 결정적으로 수행하고, 3~5단계는 플래너가 `reviewSituations`(상황 + 원문 clause + 근거 ID)를 받아 수행
- 상황은 어휘 목록이 아니라 **문법**(동반·수혜·목적·시간·시점 구문)으로 식별 — 저장소가 모르는 상황("야근할 때")도 추출됨. ko/ja/en 공통 경로
- 상황 출처는 **리뷰와 공식 상품 카피 둘 다**이며 같은 상황이면 공식 카피 우선. 리뷰 0건 상품에는 공식 카피가 유일한 CEP 소스
- 리뷰는 **추천하는 리뷰만** 사용. 평점이 있으면 평점이 정본(5점척도 ≥4, 10점척도 ≥8), 없으면 산문 판정
- `isPositiveReviewItem`/`isPositiveReviewBody` 신설 — 기존 `isNegativeReviewSignalText`는 짧은 구 전용이라 문장에 적용하면 부정 범위를 못 읽어 5점 리뷰를 오판한다(벤치마크 픽스처 3건 중 2건). 신규 판정기는 부정("자극 없이")과 해결("속건조를 잡아주는") 구문이 불만 단서를 상쇄하는지로 판단
- 상황은 리뷰/카피에서, **need와 모든 상품 주장은 공식 필드에서만** — 리뷰는 경험 근거라 효능·적합성을 만들 수 없음
- 루틴 단계("세안 후"), 수량 span("사용 4주 후"), 무의미 조각은 CEP에서 제외. 정규화가 리뷰 본문을 `sourceTexts`에 복사하므로 공식 출처로 읽을 때 걸러내 리뷰가 극성 게이트를 우회하지 않도록 함

**FAQ 중복 제거**

- 상황형 적합성 질문에 별도 dedupe 앵글(`situational-suitability`) 부여 — 대상고객형과 다른 검색 표면이므로 서로 흡수하지 않음(`generate`/`validate` 이중 구현 동시 갱신)
- 시험 결과를 묻는 효능 FAQ가 구성 FAQ의 도입부를 반복하지 않고, 물어본 시험을 먼저 답하도록 변경
- 제형 FAQ는 상품 카피가 제형을 서술할 때만 리뷰 사용감 FAQ와 함께 발행. 근거가 리뷰뿐이면 출처를 밝히는 리뷰 FAQ만 남김
